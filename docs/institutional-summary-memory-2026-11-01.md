# Institutional summary storage, November 1, 2026

The accepted 6,472-original cohort exceeds the existing 20,000,000-byte represented-summary budget for ordinary mixed retry plans. Publication remains disabled. Raising the limit or dropping large filings is not the proposed repair.

The local change shares exact, case-sensitive CUSIP names within each reporting period. It preserves Decimal totals and divides in the caller's Decimal context. The initial twenty-target plan falls from 22,635,166 to 18,808,034 represented bytes and matches every complete target-value hash after checking all 6,472 originals. Its initial Windows preparation plus oracle comparison takes 139.984 CPU seconds; this is not production capacity proof. A mixed retry plan still exceeds the limit, so dictionary sharing alone does not close the issue.

For larger plans, batch preparation now has a temporary-file fallback. It retains source identities, hashes and offsets in memory and streams exact immutable totals from a private temporary file. Every stored record has a length and SHA256 check; all original files still undergo the existing complete validation before publication. The represented resident-summary limit stays 20 MB, each decoded record has the same bound, and the temporary file is capped at 128 MB. These are explicit representation and file bounds, not a claim that total process RSS stays below 20 MB. Existing raw-document, scan, target, resource and publication guards remain separate.

Small batches create no temporary file. The file is sealed before reading, unlinked immediately on POSIX or deleted on close on Windows, and closed on successful publication and downstream failures. A new batch never reuses derived files from an earlier batch. No persistent cache, database schema, source flag, schedule, subscription or host change is introduced.
