# Shared primary-statement revenue recovery

October 18, 2026. Implemented and locally validated; release and ordinary production refresh pending.

## Problem and coverage evidence

The current aggregate audit covers 1,781 scopes and still reports 368 lost legacy classifications. Of 151 missing-scored-field cases, 119 lack current operating margin and 128 lack its prior comparison; many require accounting or source coverage beyond a generic tag fallback. Aggregate receipts classification-gap-diagnosis-1792294933.json and classification-gap-diagnosis-1792294974.json contain no private record exports.

An offline audit of 234 retained public SEC source pairs identifies a shared revenue failure: a newer `Revenues` concept can have incomplete annual history while the contract-revenue concept has complete history. Exact overlaps alone do not establish that a component is total revenue. KELYA has 13 exact overlaps, KGS four and WAT six; GCT has only six of 14 and must stay held. Complete-source artifacts are under artifacts/revenue-series-oct18 in the primary workspace; the committed test fixtures retain 18 compressed public originals with URLs, byte hashes and filing identity.

## Implementation

The shared reader has no new ticker eligibility list. It requires an unambiguous, completed, current domestic filing, one unchanged contract-revenue history, at least two exact total overlaps, and original consolidated statement proof for every annual/YTD input. Currency, issuer, accession, filing date, period, values and original bytes are bound to the selection. A service-revenue label additionally requires the independently reported cost-of-services and gross-profit equation. Explicit missing values, source conflicts, missing originals and changed identities remain held.

Existing reviewed AEVA/ALLE policies retain priority. The current original is reused and acquisition stays within the existing six-document transport bound. Failed supplementary proof preserves independently valid inline metrics. Provider flags, source budgets, schedules, market inputs and scoring formulas are unchanged. Existing cache TTLs remain in force; no forced refresh is used as scheduled acceptance.

Core trailing-year calculations receive one qualified revenue concept. The historical reader separately retains existing reported periods and adds original-verified periods. Fourth-quarter/half-year derivations require a matching concept before claiming a chart slot. No calculation combines a component and a total from different concepts.

## Validation and limitations

Initial integration exposed an extra-request regression for existing reviewed policies; priority was restored. A negative original-heading test exposed narrative references being mistaken for a primary title; the reader now requires an actual statement heading. The history comparison then exposed lost chart slots for uncomputable mixed-concept derived periods; eligibility now checks the concept before selection. These failures were repaired, not waived.

The expanded Linux suite completed with 279 passes and one chart-history failure before the final chart-slot repair. All 82 affected source/chart/cache/native tests pass on the corrected revision in 103.07 seconds. Together these runs cover 308 distinct passing test cases, including the corrected failure; this is not a claim of a full repository suite pass. The first expanded invocation used a nonexistent test filename and ran no tests; it is not validation. Linux Python 3.12.3 emitted only existing FastAPI lifespan deprecation warnings.

The local installed-verifier rehearsal passes 28 file hashes, all 18 originals, exact core values, preserved chart rows, prepared/cache repeats and the conflicting-source hold. It uses isolated SQLite and denies network connections; zero production record reads, writes or emails. Windows Python 3.14.2 CPU was 27.86 seconds. This is not deployed Python or sustained-capacity evidence.
